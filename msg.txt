feat: Android Keystore sealer for qualia-bioauth

The Rust crate seals nothing itself on Android: an auth-bound key lives in
the Android Keystore, and using it needs a BiometricPrompt attached to an
Activity's UI thread, which a library cannot host. This repository is that
half.

KeystoreBiometricSealer creates an AES-256-GCM key with
setUserAuthenticationRequired(true) and runs every cipher through
BiometricPrompt, so the platform refuses to use the key until the user has
authenticated. A new biometric enrolment invalidates the key, which makes a
stored envelope stop opening rather than silently accept the new finger.

Envelope is version(1)||ivLength(1)||iv||ciphertext, and its reader rejects
an unknown version, a different IV length, truncation and a buffer with no
room for the tag: the bytes come from a file, so they are checked before
anything indexes into them.

Availability separates Unavailable (this device or user cannot use the
mechanism) from Unsupported (the API level cannot provide it at all), so a
caller keeps its password path with the right explanation.

Publication targets Maven Central through a local staging directory that CI
zips and uploads to the Central Portal, with the tag matched against the
declared version first.
